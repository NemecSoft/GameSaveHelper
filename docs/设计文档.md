# GameSaveHelper 设计文档

> 更新时间：2026-09-08

## 1. 项目概述

通用游戏存档备份助手，分两端：

- **备份端** `GameSaveHelper.exe`：按「游戏名」或「路径 + 通配符」收集存档文件，自动填充 NSIS 模板并调用 makensis 编译出一个**自解压恢复包 exe**，默认放在系统桌面。
- **恢复包**（生成出来的 exe）：双击打开，显示要恢复的路径（可修改），点「恢复存档」一步还原到原位置。

技术栈：纯 Win32 C++（静态链接 CRT，单文件约 286 KB，无运行时依赖）+ NSIS 3.x。

## 2. 目录结构

| 路径 | 说明 |
|---|---|
| `GameSaveHelper.exe` | 主程序（备份端入口） |
| `config.json` | 游戏名 → 存档路径数组（"只有游戏名"模式用） |
| `template\GameSaveHelper.nsi` | NSI 模板，`@@占位符@@` 由主程序填充 |
| `nsis\makensis.exe` | NSIS 编译器发行包（仓库自包含） |
| `src\GameSaveHelper.cpp` | C++ 源码 |
| `build.bat` | 一键编译主程序（MSVC + Windows SDK） |
| `push-to-git.bat` | 幂等的 git 推送脚本 |
| `tools\screenshot-window.ps1` | 启动 exe → 截窗口图 → 杀进程（界面自测用） |
| `logs\GameSaveHelper.log` | 运行日志（UTF-8，含每次成功/失败详情） |

## 3. 备份端设计

### 3.1 命令行（严格模式，不做推断）

```bat
:: 方式一：游戏名 + 路径参数（引号包裹，支持通配符）
GameSaveHelper.exe 大富翁11 "D:\games\Z\Richman 11\2074800\*.*" "D:\games\Z\Richman 11\settings\*.*"

:: 方式二：只有游戏名 → 从配置文件按游戏名读取 savePaths/存档路径
GameSaveHelper.exe 大富翁11

:: 方式二变体：用 /config: 指定配置文件位置
GameSaveHelper.exe SparkingZERO /config:"D:\其他位置\games.json"
```

- 第一个参数必须是游戏名（不能是路径、不能是选项）
- 其余非选项参数必须是完整路径（含盘符或分隔符），否则报「参数错误」
- 无参数：弹红标题错误窗口「备份失败，参数错误，请联系管理员...」+ 用法说明
- 选项：`/q` 静默（脚本调用，不出窗口，错误写 stderr）、`/nr` 不递归、`/out:目录` 指定输出目录、`/config:文件` 指定配置文件
- 退出码：成功 0，失败 1，参数不合法 2（静默模式参数错误也直接退出，不弹窗）

### 3.2 备份流程（RunJob）

1. **扫描**：逐位置检查目录存在性 + 通配符匹配（`FindFirstFile`，递归）。
   绝不用 `CreateFile` 探测文件占用（那本身就是锁文件）；文件被占用时由 makensis 读取失败自然报错。
   异常（目录不存在 / 无匹配文件）→ 中止并逐条列出原因。
2. **生成 NSI**：读模板（优先 exe 同目录 `template\GameSaveHelper.nsi`，否则用内嵌资源 RCDATA），替换全部 `@@占位符@@`，写 `build\游戏名.nsi`（UTF-8 BOM）。
3. **编译**：探测 makensis（exe目录\nsis\ → exe目录 → Program Files → 注册表 → PATH），隐藏窗口运行，输出重定向到 `build\makensis.log`。
4. **产物**：`存档备份【游戏名】_YYYYMMDD_HHMMSS.exe`（游戏名做文件名非法字符清洗）。

### 3.3 主窗口界面

- 白底现代布局：顶部 **13pt 加粗状态标题**（进行中蓝 `RGB(0,103,192)` / 成功绿 `RGB(16,124,16)` / 失败红 `RGB(196,43,28)`）+ 浅灰卡片只读详情区（`RGB(246,246,246)` 底）+ 细 marquee 进度条 + 底部「关闭」「显示备份后的文件」按钮
- 客户区 640×400，按 `SPI_GETWORKAREA` **屏幕居中**（略偏上 1/3 处）
- 参数合法时打开窗口即自动开始备份；备份进行中禁止关闭窗口（防 makensis 被中断）
- 成功后详情区显示：备份文件完整路径、文件大小、备份时间、**恢复路径列表**、使用方法 3 条（网盘带走 / 双击一键还原 / 微信 .tmp 说明）
- 「显示备份后的文件」：`explorer.exe /select,"路径"` 打开目录并定位到文件（不自动打开）；失败时该按钮变「查看日志」
- 失败时逐行显示原因 + 日志路径；所有结果都追加写入 `logs\GameSaveHelper.log`

### 3.4 配置文件（两种格式，按内容自动识别）

**格式一：games.json（Playday 导出格式，优先）**——顶层数组，每项含 `name` 和 `savePaths`：

```json
[
  {
    "name": "SparkingZERO",
    "savePaths": [
      "X:\\YunGame\\X\\SparkingZERO\\SaveGame\\*.*",
      "X:\\YunGame\\X\\SparkingZERO\\settings\\*.*"
    ]
  }
]
```

**格式二：config.json（简易映射）**：

```json
{
  "大富翁11": [
    "D:\\games\\Z\\Richman 11\\2074800\\*.*",
    "D:\\games\\Z\\Richman 11\\settings\\*.*"
  ]
}
```

**查找顺序**：`/config:` 指定文件 → 当前目录\games.json → 本程序目录\games.json → 当前目录\config.json → 本程序目录\config.json → `D:\AI\Code\Playnite\Playday\games.json`（内置兜底，位置可在源码 `LoadConfigPaths` 里改）。

内置零依赖的针对性 JSON 解析。**宽容解析**：Playday 导出的 games.json 数据有多处坏转义（`"...*.*\"` 把收尾引号转义掉、`\\"` 后跟多余引号、数组元素之间缺逗号），标准 JSON 解析会失败；程序用「缩进锚点 + 宽容字符串读取」直接定位游戏级 `name` / `savePaths`（游戏级字段缩进固定为 2 个 Tab，嵌套的 actions 等更深不会误命中），并清洗路径值末尾多余的反斜杠/引号。

### 3.5 程序设置 settings.json（exe 目录，可选）

```json
{
  "gamesJson": "D:\\AI\\Code\\Playnite\\Playday\\games.json",
  "nsis": "nsis\\makensis.exe",
  "outDir": "",
  "recurse": "true"
}
```

| 键 | 说明 | 缺省 |
|---|---|---|
| `gamesJson` | games.json 配置文件路径（存档路径来源） | 内置兜底 Playday 路径 |
| `nsis` | makensis.exe 路径，相对路径相对 exe 目录 | 依次探测 exe目录\nsis\ → Program Files → 注册表 → PATH |
| `outDir` | 备份包默认输出目录 | 桌面 |
| `recurse` | 是否递归扫描子目录 | true |

查找顺序变为：`/config:` 指定文件 → 当前目录\games.json → exe目录\games.json → 当前目录\config.json → exe目录\config.json → settings.json 的 `gamesJson` → 内置兜底路径。

**备份位置容错**：目录不存在 / 空目录的位置记为警告并跳过，只要有一个位置有文件就正常出包；全部位置都没文件才报「备份失败，没有存档或者存档被锁定了」。跳过的位置在成功详情里列出。

## 3A. Release 部署

`build-release.bat`（可带参数指定 gamesJson 路径，`set SKIP_NSIS=1` 跳过 NSIS 复制）生成：

```
release\
  GameSaveHelper.exe          主程序
  settings.json               程序设置（gamesJson / nsis / outDir / recurse）
  template\GameSaveHelper.nsi NSI 模板
  assets\icon.ico             恢复包图标
  nsis\                       NSIS 编译器（SKIP_NSIS=1 时不带）
  备份_从配置读取_游戏名.bat   便捷入口：备份_从配置读取_游戏名.bat 游戏名
```

整个 release 文件夹拷到目标机器即可；路径变化直接编辑 `release\settings.json`。

## 4. 恢复包设计（template\GameSaveHelper.nsi）

### 4.1 界面

- 单页面（nsDialogs），**微软蓝横幅** `#0078D4` 48u：白色加粗标题「游戏名 恢复存档」+ 浅蓝副标题（备份时间 · N 个位置 / M 个文件）
- 「恢复到以下位置（可以直接修改）」：每个位置一行文本框 + 浏览按钮（nsDialogs::SelectFolderDialog）
- 灰色提示「点「恢复存档」开始...」
- 底部按钮：`恢复存档`（正常尺寸）+ `关闭`，藏起「上一步」
- 文案统一用「恢复存档」，不用「还原/备份」

> 踩坑记录：nsDialogs 里**不要用整页 100%×100% 的 label 当白色背景**——它会盖住后续创建的 EDIT/BUTTON 控件（路径输入框消失），而 LABEL 控件不受影响，非常隐蔽。1018 页面本身是白的，直接删掉背景 label。

### 4.2 恢复流程

1. 读各路径框 → 覆盖检查：目标位置已有文件时弹确认框（列出全部位置），用户确认才继续
2. `File /r` 解压到 `$PLUGINSDIR\pN` → `CopyFiles` 回原路径，逐位置统计成功/失败
3. 结束弹窗：「恢复完成，共 N 个位置」或「成功 X 个，失败 Y 个（多半是游戏占用，先关游戏再试）」，然后退出

### 4.3 静默模式

`恢复包.exe /S`：不弹窗，直接恢复到备份时的原位置。

### 4.4 模板占位符

`@@BUILD_TIME@@` `@@PRODUCT_NAME@@` `@@BACKUP_TIME@@` `@@BACKUP_STAMP@@` `@@TOTAL_FILES@@` `@@TOTAL_SIZE@@` `@@PART_COUNT@@` `@@OUT_FILE@@` `@@ICON_LINE@@` `@@PART_VARS@@` `@@PART_INIT@@` `@@PART_CREATE@@` `@@PART_LEAVE@@` `@@PART_OVERWRITE@@` `@@PART_RESTORE@@` `@@TIP_Y@@`

## 5. 构建

```bat
build.bat        :: 需要 MSVC + Windows SDK（脚本自动探测版本）
```

流程：`rc.exe` 编资源（模板 nsi + 图标内嵌进 exe）→ `cl.exe /MT /O2` 编译 → `link.exe /SUBSYSTEM:WINDOWS` 静态链接单文件。
**改了 template\GameSaveHelper.nsi 或 src 源码后必须重跑 build.bat**（模板是内嵌资源）。

## 6. Git

- 已忽略所有编译产物（`build\` `out\` `logs\` `*.obj` `*.exe` 等），源码 + `nsis\` 发行包入库，仓库自包含
- `push-to-git.bat`：幂等推送（init/add/commit/push，无变更跳过提交），提交信息自动带时间「更新 %date% %time%」
